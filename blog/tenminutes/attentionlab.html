The semantic
tug-of-war.

Attention is the one place inside a transformer where a token can take information from another token. Query, key, value: what am I looking for, what do you contain, what will I carry away? Click a word and watch the sentence decide what it means.

01 The problem

A word is not a meaning until it has neighbours.

“Apple” in isolation is ambiguous. In I ate a juicy apple, the word “juicy” pulls its vector toward the fruit cluster. In Apple released a new chip, “released” pulls it toward the company cluster. A static embedding cannot do that; it gives every occurrence of “apple” the same vector. Attention is how the model rewrites the vector using the other words in the context.

The classic case is “bank”: river bank or money bank? The sentence must decide. Attention lets each token ask the rest of the sequence: which of you matters to me right now? The answer is a weighted average, not a dictionary lookup.

The aha

Meaning is movement.

The contextual vector of “bank” is not its dictionary entry; it is a new position produced by the gravitational pull of the words it attends to.

02 The handshake

Query, key, value.

For every token, the model computes three vectors by multiplying its hidden state with three learned matrices:

  • Query (q) — what this token is looking for.
  • Key (k) — what this token offers as a descriptor.
  • Value (v) — the content this token will pass on if chosen.

The score between a query and a key is their dot product, scaled by the square root of the key dimension. A large score means the vectors point in a similar direction: “you are relevant to my search.” Softmax turns all the scores in a row into weights that sum to one. The output is the weighted sum of the value vectors.

scorei,j = (qi · kjT) / √dk
αi,j = softmaxj(scorei,j)
zi = Σj αi,j vj

Why divide by √dk?

As the dimension grows, dot products grow in magnitude and push softmax into a saturated regime with tiny gradients. The scaling keeps the scores in a healthy range. It changes the sharpness, not the meaning of the comparison.

04 Many heads

One sentence, many lenses.

A single head can only attend from one perspective. The transformer runs several heads in parallel, each with its own projection matrices, and concatenates their outputs. In the original paper there are 8 heads over a 512-dimensional model, so each head works in a 64-dimensional subspace. One head can chase syntax while another tracks coreference; the final output projection mixes them back together.

This is not redundancy. Studies of BERT find that a small number of heads do most of the work, some specialize in dependency relations, and many can be pruned with little loss. But no single head is a clean parser, and much attention lands on punctuation or special tokens. The picture is distributed: syntax is partitioned across heads and depth, built bottom-up, not read off one tidy tree.

Softmax is zero-sumEach row sums to one. If one key gets more attention, every other key gets less. Attention is a finite budget.
Columns are not zero-sumSome tokens become information hubs, receiving attention from many queries.
Context windowAttention can only see tokens inside the window. Memory and compute grow quadratically with window size.
KV cacheDuring generation, past keys and values are cached so each new query need not recompute the whole prefix.

Two beautiful connections are worth knowing. The attention operation is a differentiable read head over a memory tape: query = address request, keys = address tags, values = content. And modern Hopfield networks show that attention is mathematically an associative memory retrieval. RAG extends the same idea outside the model: retrieve documents by similarity and put them in the context window.

There is also a strange corner case: attention sinks. In many decoder-only models, a large share of attention flows to the first token even when it carries no content. When streaming with a sliding window, evicting that first token can collapse the model; keeping a few sink tokens pinned fixes it. The model is not remembering their meaning — it is using them as a resting place for the attention budget.

05 The limits

An attention map is not an explanation.

It is tempting to read attention weights as “the model looked here.” That is only partly true. The weights show where information was routed at one layer and one head; they do not show what the feed-forward network did with it, how the residual stream carried it, or whether the head is causally important. Attention is a mechanism, not a confession.

The honest summary: attention is a learned, soft, differentiable routing scheme. It is powerful because it lets every token see every other token in one step, and it is limited because the routing is probabilistic, the context is finite, and the weights are not a human-readable explanation.

Common misreading “The model builds a syntax tree and then reads it.” Syntax is distributed across heads and layers, not stored as one parse object.
Better frame “Many specialist heads, coordinated through the residual stream, build structure bottom-up.” The representation is relational and distributed.
Common misreading “High attention weight means the model used that token.” The value path and the rest of the network decide what actually matters.
Better frame “Attention routes information; the FFN and residual stream compute with it.” Interpretability needs both the routing and the computation.
