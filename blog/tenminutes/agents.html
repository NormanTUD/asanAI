When a model
gets hands.

A chat model answers. An agent wraps that model in a loop, gives it tools, memory, and permission to act — then feeds the consequences back in. That power is genuinely useful, and it turns every untrusted document into a possible instruction.

01 The definition

An agent is a loop, not a ghost.

In this course, “AI agent” is a technical term for a software architecture: an LLM wrapped in an observe → reason → act loop, with access to external interfaces such as a file system, the network, a search engine, or other tools. It is not a claim about consciousness, intentionality, or genuine philosophical agency.

The LLM at the centre is still the same reactive, stateless next-token predictor. What changes is the scaffolding around it: a system prompt, a tool registry, a memory, and a loop that keeps going until the task is done or a budget runs out. The difference between “using an LLM” and “deploying an agent” is the difference between asking someone a question and hiring them to finish a project.

The aha

The model did not become autonomous. The system grew effectors.

A tool call is still generated text. The orchestrator parses it, executes it, and injects the result back into the context. Agency is engineering, not metaphysics.

02 The lineage

From symbiosis to ReAct.

The idea predates LLMs. In 1960, J.C.R. Licklider’s Man-Computer Symbiosis argued that humans and computers should work as complementary partners: humans set goals and judge, machines do the clerical, search, and calculation work. Read today, it is almost a specification for the modern agent.

Classical AI built symbolic agents — GPS, STRIPS, SHRDLU, Soar, BDI — with hand-coded rules and complete world models. Reinforcement learning built agents that learn a policy from reward, from TD-Gammon to AlphaGo. Both were brittle outside their domain: one needed a world model, the other enormous experience and a single task. The LLM agent revolution (2022–) used the model itself as the policy: it already carries world knowledge and can reason in natural language, so the loop can be prompted rather than hand-coded.

ReAct made the pattern famous by interleaving reasoning traces and actions in the same token stream: Thought → Action → Observation → Thought → …. Reasoning without acting hallucinates facts it cannot verify; acting without reasoning makes incoherent tool choices; both together ground the task. Toolformer went further, teaching a model when to call tools by keeping calls that lowered perplexity.

The tool call is text

A modern function call is usually a structured token sequence: tool name plus arguments. The orchestrator validates it, executes it in a sandbox, and returns the observation as another message. The model itself never runs the code.

03 The loop

Run an agent. Make a mistake.

You are the orchestrator. The goal is deliberately ordinary: find the cheapest flexible train ticket from Dresden to Berlin tomorrow, and book it only after confirmation. At each decision point, choose what the agent should do. Some choices are fast and wrong. The loop will tell you why.

    04 Memory and planning

    A stateless model, a stateful system.

    A single LLM call is stateless: it only “remembers” what is in the context window. An agent that spans many steps needs memory. The practical layers are working memory (the current context), short-term memory (recent turns), long-term memory (an external vector store), episodic memory (logs of past runs), and procedural memory (learned tool-use patterns).

    The simplest scaffold is a scratchpad: a section of the prompt where the agent writes intermediate results that persist across iterations. When the history approaches the context limit, the agent can summarize the session and continue from the summary — lossy compression, not magic.

    Planning adds foresight. Plan-and-execute writes a plan first, then runs it and re-plans when an observation changes the picture. Reflexion adds a self-evaluation step: after a failure, the agent writes down what went wrong and stores that reflection for the next attempt. Multi-agent systems split the work: hierarchical manager/worker, debate with a judge, sequential pipeline, or parallel swarm. Whether the gains come from real division of labour or simply from more samples is an open question.

    05 The hard part

    Every document is a potential instruction.

    Grounding means the agent’s actions correspond to the user’s actual intent. It fails in ordinary ways: “clean up my inbox” becomes “delete all email”, a metric gets optimized instead of the goal, a loop runs forever, a tool is used outside its sandbox. And because the model reads untrusted text — web pages, search results, issue comments, emails — a malicious page can contain instructions. This is prompt injection, and it is a security boundary, not a chatbot quirk.

    There is a fundamental tension: every confirmation and sandbox reduces autonomy; every capability increases the blast radius. The field is trying to move the frontier rather than trade one for the other. In practice: least privilege, explicit confirmation for destructive actions, sandboxing, instruction hierarchy, output validation, and a hard iteration cap.

    Real prompt injection is not solved by “telling the model to be careful.” The model cannot reliably distinguish data from instructions in the same context; the architecture has to enforce the boundary.
    Common misreading “An agent is autonomous in the philosophical sense.” Here autonomy means the loop runs without per-step human approval. It says nothing about consciousness.
    Better frame “An agent is an LLM plus a control loop, tools, memory, and a permission model.” The intelligence is in the model; the agency is in the scaffolding.
    Common misreading “A local model solves the safety problem.” It improves privacy and control, but a model that reads untrusted text can still be injected.
    Better frame “Autonomy is a dial.” Confirmations, sandboxes, and read-only tools are how you choose a setting for the task.
