Before you start · a note on method

A machine that guesses. A course that slows down.

AI is usually explained as either magic or a product. This course takes a third route: start with the smallest honest picture — a model predicting the next token — and follow the dependencies until the whole stack is in view. This page is the short argument for why that route is worth ten minutes.

01 The wager

A stack of ordinary ideas.

Most explanations of AI fail in one of two ways. They keep the machine at a distance — a black box, a miracle, a threat — or they drown you in details before you have a reason to care about them. Either way, you can use the tool and still have no idea what it is doing.

This course makes a wager: the interesting thing is not a single clever algorithm. It is a stack of ordinary ideas that become strange when they are composed at scale. A next-token predictor is not intelligence. But a next-token predictor with a large vocabulary, a deep transformer, a carefully curated corpus, and a post-training pipeline starts to behave like something we do not have a good word for.

The way to understand that stack is not to memorise the names of its parts. It is to see how each part depends on the one below it. That is the route this course follows.

02 The method

One idea, then its dependencies.

Start with one prediction. The model reads a context and returns a probability for every token that could come next. Pick one, append it, and ask again. That loop is the engine. The rest of the course is the machinery that makes the engine good: tokens, vectors, attention, training, post-training, retrieval, tools.

Each chapter answers a question the previous chapter made unavoidable. If the model predicts tokens, what is a token? If tokens become vectors, what is a vector? If attention mixes vectors, what is it mixing, and why does position matter? If the model is trained, what is being changed? If it becomes an assistant, what was added after training? If it is deployed, what does it do to the people who use it?

This is a dependency chain, not a syllabus. You can enter anywhere, but the order is there for a reason: it lets each idea stand on something you already have.

03 This edition

A doorway, not the library.

The Ten Minutes edition is the doorway, not the library. Each page gives you one idea, one demo or example, and a clear takeaway. It is deliberately shorter than the longer course; it is not a replacement for it, and it does not pretend that ten minutes is enough to master the subject.

The short version is useful precisely because it is short. It gives you a correct first map: enough to ask better questions, enough to recognise the shape of the machine, enough to know which thread you want to pull. The longer course is where the derivations, the sources, and the edge cases live.

04 The open question

What is it doing?

The course does not end with a verdict. It ends with a question that gets sharper as you go: if a model can predict the next token well enough to write code, argue, translate, and explain, what exactly is it doing? And what are we doing when we call that understanding?

The answer is not in any single chapter. It is in the stack: the data, the architecture, the training, the post-training, the interface, and the society that uses it. The point of the first pass is to let you see that stack clearly enough to disagree with it.

So: when a model finishes your sentence, has it understood anything — or has it only learned the shape of the sentence?
