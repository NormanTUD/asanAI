The model can think longer.

For years, scaling meant training a bigger model. Reasoning models add another axis: give the model more computation at inference time and let it explore, check, and revise.

01 Thinking in the open

Use the context as a scratchpad.

Chain-of-thought prompting (Wei et al., 2022) asks the model to write intermediate steps instead of jumping to an answer. On arithmetic and logic, this often improves accuracy because the model can use the context as a scratchpad. It is not a different model or a hidden reasoning module: the model is still predicting tokens, but the intermediate tokens give the later predictions more to condition on.

Self-consistency (Wang et al., 2022) samples several reasoning paths and takes the majority answer. Tree of thoughts (Yao et al., 2023) explores branches and evaluates them. These methods trade more computation for better answers. They work best when the problem has a checkable answer and the model's errors are not correlated; if every path makes the same wrong assumption, voting does not save you.

02 Learning to reason

More compute, more checking.

The o1/R1 generation goes further: the model is trained with reinforcement learning on problems that can be checked (Shao et al., 2024), so it learns when to think longer, backtrack, and verify. The reasoning process can be much longer than the final answer. A user-facing “summary of reasoning” may be only that — a summary. It is not a guaranteed transcript of the computation that produced the answer, and a fluent explanation can be reconstructed after the fact.

More thinking is not always better. The model can reason confidently in the wrong direction, and long chains are expensive. The useful question is whether the extra computation buys a real improvement on the task, not whether the explanation sounds thorough.

03 When thinking longer helps

Verification is the bottleneck.

Chain-of-thought gives the model a scratchpad. Self-consistency samples several paths and compares answers. Tree of thoughts explores branches. All of these methods spend more computation at inference time in exchange for a better chance of finding a correct path.

The o1/R1 generation trains the model to use that computation. Reinforcement learning on problems with verifiable answers teaches it when to backtrack, when to check, and when to stop. Process reward models can score the intermediate steps, not only the final answer.

More thinking is not always better. Long chains are expensive, and a model can reason confidently in the wrong direction. The useful question is whether the extra computation buys a real improvement on the task, and whether the steps can be checked.

Problem: A bat and a ball cost $1.10. The bat costs $1.00 more than the ball. How much does the ball cost?

Let the ball cost x. Then the bat costs x + $1.00.
x + (x + $1.00) = $1.10.
2x = $0.10, so x = $0.05.
The ball costs $0.05; the bat costs $1.05.

Answer: $0.05.

Background

Process Reward Models (PRMs)

A process reward model (PRM) (Zhang et al., 2024) scores each intermediate step, not only the final answer. That is a better training signal than a single right/wrong label: it can tell the model that a chain went wrong at step two, even if it later recovered. At inference, beam search guided by the PRM can improve accuracy on math; the cost is labelling data, and synthetic PRMs (auto-labelling with a stronger model) are now competitive.

Background

Inference-Time Scaling Laws

Compare this with training: achieving 85% on AIME, the American Invitational Mathematics Examination, by training alone would require either a much larger base model or domain-specific data (Snell et al., 2024). Inference-time scaling is often cheaper and more flexible — but it moves the cost to every query rather than paying it once. A model that thinks for ten thousand tokens on every request is expensive to serve, which is why adaptive thinking matters.

Background

Summary

The era of “scale by training” is now supplemented by scale by thinking. The frontier in 2025 is figuring out how to spend inference compute adaptively, think hard when it matters, save tokens when it doesn't.

Practical notes

More tokens, more money, more risk.

Reasoning with more tokens costs more compute and latency. It can improve hard maths and code, but it can also make a model stall, loop, or justify a wrong answer with more confidence.

The useful pattern is generate, then verify. Use a checker when the answer can be checked; use a second model or a different prompt when it cannot. More thinking is a tool, not a universal upgrade.

The fine print

What the benchmarks show.

Chain-of-thought and test-time compute improve hard maths, code, and multi-step logic, but they are not a universal upgrade. On simple tasks they can add cost and latency without improving the answer. On some tasks they can make a wrong answer look more considered.

The evaluation question is whether the model is better at the task, not whether the reasoning text sounds good. A correct answer with a flawed chain and a wrong answer with a perfect-looking chain are both possible. Verification is the difference between thinking and performance.
