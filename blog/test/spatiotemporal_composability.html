The Two Dimensions of Dynamic Composability

Modern software increasingly demands dynamic composition — loading, unloading, and reconfiguring components at runtime. Plugin systems (like VSCode) and AI agent harnesses need this, but current practice just restarts the whole process. Cordis identifies two orthogonal dimensions:

⏱️ Temporal Composability
When you remove a component, every side-effect it caused must be reversed. Every allocation, event listener, and state change must be tracked and undone in order.
🕸️ Spatial Composability
Components must declare their dependencies on each other and be reactively activated/deactivated as providers appear and disappear.

Revertible Effects: Every Action Carries Its Undo

An effect is modeled as a function Γ → Γ × (Γ → Γ): it transforms the context and returns an inverse. Inverses are composed onto an accumulator in LIFO order. When the component unloads, the accumulator runs and undoes everything perfectly.

Accumulator (LIFO Inverses)
🔑 Key insight: Each effect pairs its forward action with an inverse. When unloaded, inverses run in reverse order (Last-In-First-Out) — subscribe first, then bind, then open — so each inverse meets exactly the state its forward action produced. This is Theorem 16 in the paper.

Reactive Coeffects: Dependencies That Wake You Up

A component declares which coeffects (dependencies) it needs. The runtime classifies every context change against the specification: activating, deactivating, or neutral. Components spring to life when their deps are ready, and gracefully deactivate when they vanish.
