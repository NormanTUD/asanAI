Basis + strukturierte Koordinate

Fusion aus: posembed8.html ✕ space_morph.html

Derselbe Zug, zwei Fälle: Eine erhaltene Basis wird in einer höheren Dimension um eine strukturierte Koordinate erweitert, die eine (nichtlineare) Funktion eines Attributs des Objekts ist. Genau diese zusätzliche Koordinate macht, was vorher unterscheidbar-unmöglich war, linear lesbar.

1Kernthese der Fusion

Beide Papiere sind zwei Gesichtsebenen eines einzigen Mechanismus: Untrennbares wird trennbar, indem man eine strukturierte Koordinate hinzuzieht. In posembed8 (A) hat ein Wort eine feste Basis — sein Embedding e(w) (der Diamant ◆). Um jede Sequenzposition unterscheidbar zu machen, legt man einen fixen sinusoidalen Offset PE(p) darauf; das Wort beschreibt dann über die Positionen hinweg eine Helix. In space_morph (B) hat ein Punkt seine Basis (x, y); ein Layer legt dazu eine strukturierte Koordinate z = x² + y² bei und krümmt so den Raum zu einer Schale, in der eine einzige lineare Ebene die beiden Klassen trennt.

Die gemeinsame, integrierende Position lautet: Die Basis bleibt erhalten, die neue Koordinate ist eine Funktion eines Attributs — in A das Positionsindex p (ein externes Attribut des Tokens), in B der Radius r² = x²+y² (ein eigenes Attribut des Punkts). Und in beiden Fällen ist das eigentliche Ziel, dass die Menge, die man lesen will (Position bzw. Klasse), nach dem Lift eine lineare Funktion der Koordinaten ist: ein Schwellwert s = wᵀΦ(x) + b genügt, bzw. die Position wird aus dem Sinus-Code (nahezu) linear ablesbar.

Der unifizierende Ausdruck lautet Φ(a) = [Basis(a)] ⊕ [g(Attribut(a))] mit einem linearen Readout — und genau das zeigt die Visualisierung unten als eine Szene.

2Widersprüche zwischen A und B

Die beiden Papiere streiten sich nicht direkt — sie beschreiben denselben Zug. Es gibt aber drei echte Spannungspunkte, an denen sie unterschiedliche Standpunkte einnehmen:

A vs B Feste A-priori-Struktur vs. erlernte Krümmung

A setzt die Positionsgeometrie durch eine fixe, von Hand entworfene Sinus-Formel (PE) ohne jegliches Lernen — sie soll für jedes Wort, jede Position, ohne Daten funktionieren. B dagegen erzählt, dass die Krümmung des Raums ein Layer ist, dessen Parameter w aus den Daten gelernt werden; die Schale z = x²+y² passt genau diese Daten (Kern vs. Ring = Radius).

A vs B Externer Index vs. Eigenkoordinate als Treiber

In A hängt die neue Koordinate an einem externen Attribut — der Sequenzposition p —, die unabhängig vom Wortinhalt ist ( e(w) ist über alle Positionen konstant). In B hängt sie an einem eigenen Attribut des Punkts — r² ist eine Funktion von (x, y) selbst. Frage: Was trägt die Struktur — „wo bin ich in der Folge“ oder „was bin ich“?

A vs B Unterscheidbarkeit vs. lineare Trennbarkeit

A will, dass viele Positionen gegenseitig unterscheidbar sind (die Helix überschneidet sich im gezeigten Bereich nicht — injektiv). B will, dass zwei Klassen linear trennbar sind (eine Ebene genügt). Zwei verschiedene Optimierungsziele, beide über „zusätzliche strukturierte Dimensionen“ erreicht.

3Auflösung

Alle drei Spannungen lösen sich, weil sie keine Gegensätze, sondern Spezialfälle sind von: neue Koordinate = (nichtlineare) Funktion eines Attributs des Objekts, gefolgt von einem linearen Readout.

Fusion A-priori vs. a-posteriori

Die Geometrie wird fixiert, wenn das Attribut universell ist (Position/Reihenfolge ist inhaltsunabhängig — kein Datenbedarf, A), und gelernt, wenn das Attribut datenspezifisch ist (Klasse/Radius, B). Ein echtes Modell komponiert beides: fixe Positions-Encoding + erlernte Feature-Maps. Das ist kein Widerspruch, sondern die Teilung der Arbeit nach der Art des Attributs.

Fusion Extern vs. eigen

Beides ist „Funktion eines Attributs“. Position ist ein Attribut des Tokens (welche Position es besetzt); Radius ist ein Attribut des Punkts (wie weit er vom Ursprung entfernt ist). Unifiziert: g(Attribut), wobei das Attribut frei wählbar ist — p in A, r² in B.

Fusion Unterscheidbar vs. trennbar

Beide sind „die Zielgröße wird linear lesbar“. Unterscheidbarkeit der Position heißt: Position ≈ (nahezu) linearer Readout aus dem Sinus-Code (rel. Position = Skalarprodukt, PE(p)ᵀPE(q) = f(p−q)). Trennbarkeit der Klasse heißt: sign(wᵀΦ(x)+b) = Klasse. Gleiche Forderung an den Lift: die Koordinate, die die Zielgröße trägt, linear machen.

4Fusionierter Inhalt

Der gemeinsame Formkern, aus dem beide Papiere hervorgehen:

Lift: Φ(a) = [ Basis(a) ] ⊕ [ g( Attribut(a) ) ] Readout: s = wᵀ Φ(a) + b (linear) Leseziel: sign(s) bzw. ablesbare Position

Instantiierung A (Positionshelix, fix, a-priori):

Basis(a) = e(w) (konstant über p) g(p) = PE(p), PE(p,2i) = sin(p / 10000^(2i/d_model)) PE(p,2i+1) = cos(p / 10000^(2i/d_model)) Φ(p) = e(w) + PE(p) (Helix im d-dim Raum)

Jedes Dimensionspaar i schwingt mit der Wellenlänge λ_i = 2π·10000^(2i/d) — verschiedene Dimensionen = verschiedene „Gänge“. Deshalb bleibt die Spur injektiv und die (rel.) Position wird aus dem Skalarprodukt ablesbar: PE(p)ᵀPE(q) = f(p−q).

Instantiierung B (Raumkrümmung, gelernt, a-posteriori):

Basis(a) = (x, y) g(x,y) = r² = x² + y² Φ(x,y) = (x, y, x² + y²) (Schale / Einbettung ℝ² ↪ ℝ³) s = wᵀ Φ(x) + b ∈ ℝ (eine Zahl; sign = Klasse)

Abfolge: ℝ² ↪ ℝ³ ↦ ℝ — einbetten (Boden), krümmen (Layer = Verbiegung, reißt nicht), dann auf eine Zahl falten. Innere Punkte (kleines r²) sinken, äußere (großes r²) steigen → eine flache Ebene wᵀΦ(x)+b = 0 schiebt sich dazwischen; gestaut zur Linie, schließlich zum Schwellwert s = 0.

Was die Fusion daraus macht. Der Lift trägt in beiden Fällen genau eine Strukturkoordinate, die ein Attribut in seine eigene Achse hebt: A hebt Position (extern) in sinusoidale Achsen, B hebt Radius (eigen) in die z-Achse. Die Trennung/Unterscheidung ist danach nicht mehr eine Krümmungsfrage, sondern eine lineare: ein Schwellwert bzw. ein Skalarprodukt. Wer den Mechanismus so liest, sieht Positions-Encoding und Feature-Map als dasselbe Werkzeug an — „Attribut in eine Koordinate heben + linear ablesen“ — unterscheidbar nur danach, ob das Attribut universell (fix) oder datenspezifisch (gelernt) ist.

innerer Kern (Klasse A) äußerer Ring (Klasse B) Trennebene / Schwellwert Helix = Basis + PE(p) (A)

Drag: rotieren · R: Reset · β=0 → flach & untrennbar, β↑ → Schale → eine Ebene trennt. Die Helix zeigt A: dieselbe erhaltene Basis + strukturierte Koordinate.
