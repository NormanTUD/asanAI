01 · Grundlagen

Tensor-Shape-Tracking

Der Layer rechnet nie mit einzelnen Wörtern, sondern mit einem dreidimensionalen Tensor. Die Batch-Achse B und die Zeitachse T sind Containerachsen. Die eigentliche Repräsentation jedes Tokens liegt in der letzten Achse, d_model.

Der Container

Ein Token ist eine Zeile, der Layer ist eine Funktion auf allen Zeilen

Nach dem Embedding und dem Addition der Positionsinformation liegt der Input als X ∈ R^(B×T×d_model) vor. Für jedes Batch-Element und jede Position gibt es einen Vektor der Länge d_model.

X ∈ R^(B × T × d_model)

Wir folgen in der Tour dem Token „cat“ an Position 2. Seine Zeile x_cat ∈ R^d_model wird durch jede Operation geschickt. Die anderen Tokens liefern die Keys und Values, mit denen diese Zeile interagiert.

02 · Projektion & Splitting

Q, K, V: drei Rollen, drei lineare Abbildungen

Jedes Token erzeugt aus derselben Repräsentation drei verschiedene Vektoren: eine Query („wonach suche ich?“), einen Key („was biete ich an?“) und einen Value („was gebe ich weiter, wenn ich relevant bin?“). Die Projektionen sind gelernt und für jeden Head verschieden.

Die Mathematik

Pro Head: eine eigene Projektion

Für Head i wird dieselbe Input-Matrix X mit drei Gewichtsmatrizen multipliziert. Die Projektion ist eine lineare Abbildung pro Token; die Batch- und Zeitachsen werden nur mitgeschleift.

Q_i = X W_i^Q, K_i = X W_i^K, V_i = X W_i^V

Die Dimensionen sind dabei:

W_i^Q, W_i^K ∈ R^(d_model × d_k), W_i^V ∈ R^(d_model × d_v)
Ergebnis pro HeadB × T × dk
Q_i, K_i, V_i ∈ R^(B × T × d_k)

d_k = d_v = d_model/h. Im Paper: h=8 und d_k=64.

Wichtig: Die drei Matrizen sind pro Head verschieden. Head 0 und Head 1 lernen also unterschiedliche Query-, Key- und Value-Räume.

Interaktiv · Splitting

Der QKV-Block wird in h Köpfe zerlegt

Nach der fused Projektion liegen Query, Key und Value noch nebeneinander. Für die Attention wird die Feature-Achse in h Gruppen der Breite d_k zerlegt. Jeder Head bekommt seinen eigenen Q-, K- und V-Slice und rechnet unabhängig weiter.

(B,T,d_model) → (B,h,T,d_k)
Die Animation der Aufteilung ist bewusst nur eine Visualisierung: Im Speicher wird nicht wirklich kopiert, sondern nur die Achsenreihenfolge interpretiert. Ein view plus transpose genügt.
Code-Skizze

Wie das in PyTorch aussieht

Die entscheidende Zeile ist das view plus transpose: Aus (B,T,3d_model) wird pro Head ein Tensor der Form (B,h,T,d_k). 

# x: (B, T, d_model)
qkv = x @ W_qkv                       # (B, T, 3*d_model)
q, k, v = qkv.chunk(3, dim=-1)        # drei (B, T, d_model)

# (B, T, d_model) -> (B, h, T, d_k)
q = q.view(B, T, h, d_k).transpose(1, 2)
k = k.view(B, T, h, d_k).transpose(1, 2)
v = v.view(B, T, h, d_v).transpose(1, 2)
Die Batch-Achse bleibt unangetastet. Die Zeitachse wandert beim transpose hinter die Head-Achse, weil die Attention später für jeden Head eine eigene T×T-Matrix braucht.
03 · Scaled Dot-Product Attention

Wer passt zu wem?

Für jeden Head entsteht eine Matrix aus Kompatibilitätswerten. Die Query eines Tokens wird mit allen Keys verglichen, die Scores werden skaliert, optional maskiert und über eine Softmax in Gewichte umgewandelt. Mit diesen Gewichten werden anschließend die Values gemischt.

Scores

Das Skalarprodukt misst Kompatibilität

Für einen Head sind Q und K Matrizen der Form (B,h,T,d_k). Bildet man QK^T, entsteht für jedes Batch-Element und jeden Head eine T×T-Matrix: Zeile i enthält die Scores der Query i gegen alle Keys j.

S = QK^T ∈ R^(B × h × T × T)

Ein hoher Score bedeutet: Query und Key zeigen in eine ähnliche Richtung. Das Modell lernt die Projektionen so, dass diese Ähnlichkeit eine nützliche Rolle spielt, etwa „Verb sucht Subjekt“ oder „Pronomen sucht Bezugswort“.

Die Aufmerksamkeit ist nicht auf die Wortreihenfolge beschränkt. Deshalb kommt die Positionsinformation bereits vor dem Layer dazu: Ohne sie wäre die Attention permutationsinvariant.
Skalierung

Warum durch √dk teilen?

Angenommen, die Komponenten von q und k sind unabhängig, mit Mittelwert 0 und Varianz 1. Dann ist das Skalarprodukt q·k = Σ q_i k_i eine Summe von d_k unabhängigen Termen. Sein Mittelwert ist 0, seine Varianz ist d_k. Die Streuung wächst also mit der Head-Breite.

Var(q·k) = d_k, Var((q·k)/√d_k) = 1

Große Logits treiben die Softmax in eine nahezu One-Hot-Verteilung. Dort ist die Ableitung fast null, und der Gradient fließt kaum noch. Die Division durch √d_k hält die Logits in einem Bereich, in dem die Softmax weich bleibt und trainierbar ist.

Softmax-Schärfeinteraktiv

Der Regler multipliziert die Logits. Bei kleinen Werten bleibt die Verteilung breit, bei großen Werten kollabiert sie auf einen Key.

Optional · Decoder

Causal Mask: nicht in die Zukunft schauen

Im Encoder darf jedes Token alle Tokens sehen. Im Decoder ist das anders: Position i darf nur Positionen j ≤ i sehen. Vor der Softmax werden alle zukünftigen Scores auf −∞ gesetzt. Dann ist ihr Softmax-Gewicht exakt 0.

S_ij^masked = S_ij für j ≤ i, −∞ für j > i

Die Maskierung passiert vor der Softmax. e^(−∞)=0, also tragen maskierte Positionen nichts bei und die Zeilensumme bleibt 1.

Weighted Sum

Die Values werden mit den Gewichten gemischt

Die Attention-Matrix A sagt, wie stark jede Query auf jeden Key achtet. Multipliziert man sie mit den Values, erhält jeder Token eine neue Repräsentation: eine gewichtete Summe der Value-Vektoren aller Tokens.

head_i = softmax(Q_i K_i^T / √d_k) V_i ∈ R^(B × T × d_v)

Die folgende Miniatur zeigt die Rechnung für die ausgewählte Query. Jede Zeile ist ein Key mit seinem Gewicht und seinem Value-Vektor. Die Summe der gewichteten Values ist der neue Vektor dieser Query.

Die Values werden nicht mit den Keys verwechselt: Der Key entscheidet, ob ein Token relevant ist. Der Value entscheidet, was bei Relevanz weitergereicht wird.
04 · Concatenation & WO

Aus h Köpfen wird wieder ein Vektor

Jeder Head liefert eine eigene Ausgabe der Breite dv. Die Ausgaben werden entlang der Feature-Achse aneinandergehängt und mit WO zurück auf dmodel projiziert. Erst diese Projektion mischt Informationen zwischen den Heads.

Interaktiv · Concatenation

Die Head-Ausgaben liegen nebeneinander

Vier Heads, jeder mit d_v=4 Kanälen: Aus 4×4=16 Werten wird ein Vektor der Länge 16. Das ist genau h·d_v = d_model.

Projektion

WO mischt die Head-Subräume

Die Konkatenation allein addiert keine Information zwischen den Heads: Head 0 bleibt in den ersten vier Kanälen, Head 1 in den nächsten vier. Erst die lineare Projektion mit W^O ∈ R^(h d_v × d_model) erlaubt jeder Ausgabedimension, aus allen Heads zu lesen.

MultiHead(Q,K,V) = Concat(head_1,…,head_h) W^O
Bekommt jeder Head sein eigenes FFN? Nein. Jeder Head besitzt eigene W_i^Q, W_i^K, W_i^V und erzeugt eine eigene Ausgabe. Danach werden alle Heads konkateniert und mit einem gemeinsamen W^O gemischt. Das Feed-Forward Network kommt erst nach dieser Mischung, ist eines pro Layer und wird auf alle Positionen und alle Heads gemeinsam angewendet. Jeder Layer hat sein eigenes FFN, aber nicht jeder Head.

Diese Arbeitsteilung ist der Grund, warum Multi-Head Attention mehrere Beziehungen gleichzeitig modellieren kann: Die Heads spezialisieren sich auf verschiedene Subräume, W^O führt ihre Ergebnisse wieder zusammen.

Ein Mixture-of-Experts-Modell ist die Ausnahme: Dort gibt es mehrere FFN-Experten, aber die werden pro Token ausgewählt, nicht pro Attention-Head. Das ist eine andere Architekturentscheidung.
Parametrisierungpro Layer
W^O ∈ R^(h d_v × d_model)

Bei h=8 und d_v=64 ist h·d_v = 512 = d_model. Die Matrix ist also quadratisch, aber das ist keine Voraussetzung.

05 · Add & Norm

Residualpfad und LayerNorm

Jeder Sub-Layer ist in einen Residualpfad eingebettet: Der Input wird zum Output des Sub-Layers addiert. Danach normalisiert LayerNorm jeden Token-Vektor über seine Feature-Achse. Das hält die Signale stabil und öffnet einen kurzen Gradientenpfad durch den gesamten Layer.

Add & Norm 1

LayerNorm(X + Attention(X))

Die Attention verändert die Repräsentation jedes Tokens. Der Residualpfad addiert die ursprüngliche Repräsentation wieder dazu. Das Modell muss also nur die Änderung lernen, nicht die gesamte neue Repräsentation. Die LayerNorm bringt anschließend jeden Token-Vektor auf eine kontrollierte Skala.

LayerNorm(X + MultiHeadAttention(X))
Warum Residuals helfen. Der Gradient kann über die Identitätsverbindung direkt an frühere Schichten zurückfließen, ohne den Sub-Layer zu durchqueren. Bei sehr tiefen Stacks verhindert das, dass die Gradienten verschwinden oder explodieren.

LayerNorm normalisiert pro Token über die d_model Kanäle. Batch- und Zeitachse werden nicht miteinander vermischt. Deshalb funktioniert sie unabhängig von der Batch-Größe und passt zu variabler Sequenzlänge.

μ = 1/d Σ x_i, σ² = 1/d Σ (x_i−μ)², y_i = γ_i (x_i−μ)/√(σ²+ε) + β_i

γ und β sind gelernte Vektoren der Länge d_model. Sie geben dem Modell die Freiheit, die Normalisierung pro Feature wieder zu skalieren und zu verschieben.

Eingabenx und SubLayer(x)
Gelernte Affine-Parameterγ, β
Der kleine Wert ε verhindert eine Division durch null, wenn alle Werte eines Tokens gleich sind. In der Praxis liegt er typischerweise bei 10^-5 oder 10^-6.
Add & Norm 2

Dieselbe Struktur nach dem FFN

Nach dem Feed-Forward Network folgt der zweite Residualpfad mit einer weiteren LayerNorm. Damit hat jeder der beiden Sub-Layer seinen eigenen Add-und-Norm-Schritt. Der Layer-Output hat wieder exakt die Form des Layer-Inputs.

Z = LayerNorm(X + MHA(X)), X^(l+1) = LayerNorm(Z + FFN(Z))

Post-LN und Pre-LN

Das Originalpaper benutzt Post-LN: Die LayerNorm steht nach der Addition, also LayerNorm(x+Sublayer(x)). Viele moderne Modelle benutzen Pre-LN: x+Sublayer(LayerNorm(x)). Pre-LN trainiert sich in der Praxis oft stabiler, weil der Residualpfad komplett unnormalisiert bleibt.

Warum die Form erhalten bleibt

Sowohl Attention als auch FFN liefern einen Tensor der Form B × T × d_model. Die Addition ist deshalb elementweise möglich, und die LayerNorm ändert nur die Werte, nicht die Form. Genau das macht den Layer stapelbar.

Der Output eines Layers ist der Input des nächsten Layers. Die Schnittstelle ist über alle N Blöcke hinweg identisch.
06 · Feed-Forward Network

Das position-wise FFN

Nach der Attention folgt ein kleines voll verbundenes Netz: erst breiter, dann wieder schmal. Es wird auf jede Position separat und mit denselben Gewichten angewendet. Deshalb heißt es position-wise.

Interaktiv · FFN

Erst expandieren, dann aktivieren, dann projizieren

Jeder Token-Vektor durchläuft dieselbe Kette. Die mittlere Schicht ist typischerweise viermal breiter als d_model. Die beiden großen Platten in der Mitte sind für alle vier Tokens dieselben: Das ist der visuelle Beweis für die geteilten Gewichte.

FFN(x) = max(0, xW_1+b_1) W_2+b_2
Parameter pro Layer –
Die Aktivierung ist im Originalpaper ReLU. Viele moderne Modelle benutzen GELU oder SwiGLU. Die Grundform bleibt dieselbe: lineare Expansion, nichtlineare Aktivierung, lineare Rückprojektion.
Warum so breit?

dff ≈ 4 · dmodel

Die breite versteckte Schicht gibt dem Modell einen größeren Raum, um Features zu kombinieren und Fakten zu speichern. Für das Base-Modell bedeutet das d_model=512 und d_ff=2048. Das FFN enthält damit deutlich mehr Parameter als die Attention-Projektionen.

Parametergewichtsbasiert
2 d_model d_ff + 4 d_model²

Bei 512 und 2048 sind das etwa 2,1 M FFN-Parameter und 1,05 M Attention-Parameter pro Layer, jeweils ohne Bias-Terme.

Das FFN ist position-wise: Dieselbe Funktion wird auf jeden der B·T Vektoren angewendet. Man kann es sich als zwei 1×1-Faltungen vorstellen. Zwischen den Positionen findet hier kein Austausch statt; den macht die Attention.

Wichtig: Die Gewichte sind über Positionen hinweg geteilt, aber nicht über Layer hinweg. Jeder der N Blöcke hat sein eigenes FFN. 

# x: (B, T, d_model), W1: (d_model, d_ff), W2: (d_ff, d_model)
h = gelu(x @ W1 + b1)   # (B, T, d_ff)
y = h @ W2 + b2         # (B, T, d_model)
# Dieselben W1, W2 für alle B*T Positionen.
Layer-Ausgabe

Gleiche Form, nächster Block

Der Ausgang des Layers ist wieder ein Tensor der Form B × T × d_model. Deshalb kann derselbe Block N-mal hintereinander geschaltet werden. Die Attention mischt Information zwischen den Positionen, das FFN verarbeitet jede Position danach individuell. Zusammen mit den Residualpfaden und LayerNorms ist das der vollständige Transformer-Layer.

X^(l+1) = LayerNorm(Z + FFN(Z)) ∈ R^(B × T × d_model)
Die Kurzfassung in einem Satz: Attention entscheidet, woher ein Token Information nimmt; das FFN entscheidet, was es mit dieser Information macht. Residuals halten den Informationsfluss offen, LayerNorm hält die Skala stabil.
